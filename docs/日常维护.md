# 日常维护操作

## 每次开始

1. 在 GitHub Desktop 同步本仓库的 `main`。
2. 从当前 `main` 新建工作分支。
3. 双击该仓库里的 `启动维护.cmd`，在本机网页页脚点「内容管理」。

“保存条目”会写入项目文件夹。关闭浏览器后，文件仍然在。
在 GitHub Desktop 提交变更后，可以发 PR 请负责人审核。

## 新增学习资料或工具

1. 选择“课程讲义”“体系与约定”或“常用工具”。
2. 填写网页上显示的标题。
3. 内容形式选“上传文件”或“网页链接”。
4. 选择本地文件，或填写完整的 https 地址。
5. 点“保存条目”，关闭管理窗口，检查标题、类型标记及实际下载。

网页标题和文件名可以不同。单个上传附件最大 15 MB。
更大文件可使用已有下载链接，或以后扩展附件存储。

桥牌记牌器是站内工具，源码和预览方法见[记牌器说明](../src/bridge-table/README.md)。

## 新增训练牌例

1. 选择“训练牌例”，标题可填“线下训练”，另填活动日期。
2. 选择原始 PBN，保存。
3. 在牌库中选择这场活动，检查牌号、局况和发牌人。
4. PBN 含双明手结果时会显示墩数，只含牌面也可以展示。

原始 PBN 独立保存，访问者点击下载时才请求原文件。
请保留原始牌号。更换活动 PBN 时，有关联复盘的牌号需要继续存在。

## 新增精彩牌例

1. 选择“实战复盘”，填写短标题和日期。
2. 选择叫牌、坐庄或防守分类。
3. 选择活动和牌号，或使用不关联的文字记录。
4. 填写牌桌上方引导语、叫牌面板标题和本局署名。署名选择方位并填写人名。叫牌回放的「单手视角」默认跟随署名方位，也可以单独选择。
5. 使用“添加内容段落”自行设置小标题和正文，可上移、下移或移除段落。段落不再限定为固定的三个栏目。
6. 有叫牌序列时，按发牌人起，用空格分隔依次填写。叫品提示按“序号 | 解释”逐行填写，Pass也计入序号。例如“7 | 逼局”。
7. 需要残局图时，先关联活动和牌号，再展开“残局牌图”，按黑桃 / 红心 / 方块 / 草花输入各家余牌，空门填 —，10填T。四家余牌张数需相同。设置当前出牌方和牌张（如N与SQ）。正文中填写 [[残局]] 可在该位置插入重绘牌图，已出牌自动淡化。
8. 保存后，从首页分类进入检查。

例如可填 1D Pass 4NT 5S 7D Pass Pass 7S X Pass Pass Pass。
坐庄、防守的关键过程目前可用文字记录。逐张出牌动画需要进一步扩展记录格式和播放器。

## 新增活动照片

1. 选择「活动照片」并选取照片。标题栏会自动隐藏。
2. 保存条目，在相册检查方向和内容。管理列表用文件名识别照片。
3. 工具按原比例生成最大 1440×1080 展示图及小缩略图，移除相机元数据。

公开相册按条目顺序播放。相机原图保存在你们自己的原始素材备份中。

## 修改、替换与删除

- 在条目旁点“编辑”，改文字后保存。
- 替换附件时重新选文件，保持活动与原牌号的关联。
- 删除训练活动前，先核对、处理依赖该牌例的复盘，尤其是含残局图的条目。
- 替换或删除后，旧附件可能仍留在 `media/`。按[文件规则](仓库与交接.md#文件规则)检查引用后清理。网站构建只收录有引用的附件。

## 发布和交接

1. 检查本机页面，提交目录和附件的改动，创建 PR。
2. 由负责人审核并合并到 `main`。在 Actions 确认发布成功后到正式网站验收。
3. 换电脑或交接成员时，用 GitHub Desktop 克隆仓库，安装 Python 并启动本机维护工具。

「生成发布包」和「下载维护备份」供本地使用，日常上线与同步步骤见[协作与发布](GitHub协作与发布.md)。

同一台电脑的不同标签页有版本检查。不同电脑的副本仍需按交接规则合并。
下一位维护者先取得最新项目再编辑。
