# 仓库与交接

GitHub 的 [mathematical-bridge](https://github.com/qulifang/mathematical-bridge) 是维护和发布的共同入口，每位成员各用自己的账号。交接时提供仓库链接、已上线的版本标签、维护分工、域名续费负责人，以及在处理的 PR。账号凭据、域名登录信息和私下素材请另行保管。

## 文件规则

- `content/catalog.json` 是条目和素材引用的来源。请通过「内容管理」新建、编辑或替换，保留已有条目 ID、活动 ID 和原始牌号。
- `media/` 按栏目存放附件。附件名包含所属条目及内容指纹，替换附件时工具会生成新文件。照片的展示图和缩略图一起提交。
- 替换或删除条目后，可以清理已不被任一条目引用的附件。先核对 `file.path` 和 `file.thumbnail`，再在同一个 PR 删除旧文件。历史提交仍能追溯已提交的版本。
- `src/` 和 `tools/` 保存网站和维护代码。版式或流程调整单独提交，方便和普通内容更新分别审核。
- 该仓库公开。只提交允许公开的源文件和网站素材。原图备份、未公开文稿、账户凭据、`releases/` 和 `dist/` 放在仓库之外或保留为被忽略的本机文件。

## 协作与回退

每次先同步 `main`，从新分支工作。合并以仓库中的版本为准。两个人同时改条目可能都会修改 `content/catalog.json`，提高冲突概率。遇到冲突时，初学者可从最新 `main` 新建分支，重新录入自己的改动，再对照双方内容，替换原 PR。

线上有问题时，在 GitHub 撤回相应的合并提交，或提交修正 PR。合并到 `main` 后由 Pages 再次发布，测试成功后再补充版本说明。保留已有 Release 标签作为历史记录。
